## 1. 项目概述

**Claude Code** 是 Anthropic 开发的 AI 驱动终端编码代理，作为 npm 包 `@anthropic-ai/claude-code` 发布。

| 属性 | 值 |
|------|-----|
| 版本 | 2.1.88 |
| 技术栈 | TypeScript + React（Ink 终端 UI）+ Bun（编译器） |
| 运行时 | Node.js ≥ 18（发布为单一 12MB bundle） |
| 源文件数量 | ~1,884 个 .ts/.tsx 文件 |
| 代码行数 | ~512,664 行 |
| 内置工具 | 40+ 个 |
| 斜杠命令 | ~80 个 |
| 依赖包 | ~192 个 npm 包 |
| 最大单文件 | `query.ts`（~785KB，主代理循环） |

**核心价值定位**：将 Claude 大语言模型能力与本地开发环境深度整合，使 AI 能够像人类开发者一样读写文件、执行命令、管理 Git、搜索代码库，并通过多代理协作完成复杂编程任务。

## 2. 软件需求与设计目标

通过源码分析，可以提炼出以下核心需求：

### 2.1 功能需求

| 需求类别 | 具体要求 |
|---------|---------|
| **文件操作** | 读取、编辑、创建文件；支持 PDF、图片、Jupyter Notebook |
| **命令执行** | 安全执行 Bash 命令；Windows 支持 PowerShell |
| **代码搜索** | 基于 ripgrep 的内容搜索；glob 模式文件搜索 |
| **网络访问** | HTTP 请求抓取；可选的 Web 搜索功能 |
| **版本控制** | Git 操作集成；GitHub API 调用；PR 管理 |
| **多会话** | 会话持久化、恢复、fork；跨会话记忆 |
| **多代理** | 子代理 fork；并行协作团队；远程代理 |
| **可扩展性** | MCP 协议服务接入；插件系统；Skill（技能）系统 |

### 2.2 非功能需求

| 需求类别 | 具体要求 |
|---------|---------|
| **安全性** | 工具调用权限审核；沙箱执行；路径边界检查 |
| **成本控制** | 精确的 Token 用量和美元成本追踪 |
| **上下文管理** | 自动检测并压缩超长对话，避免 prompt-too-long 错误 |
| **可观测性** | 遥测埋点（OpenTelemetry + Datadog）；详细日志 |
| **响应性** | 全链路流式输出；工具执行并行化 |
| **可移植性** | macOS / Linux / Windows（WSL）；Docker 容器；CI/CD 环境 |
| **可配置性** | 全局配置 + 项目级配置；企业托管设置 |

### 2.3 设计约束

- **运行时无依赖**：编译为单一 bundle，只依赖 Node.js 标准库
- **离线优先**：核心功能不依赖网络（API 调用除外）
- **不破坏现有代码库**：所有文件修改有撤销机制（FileHistory）

### 3.2 数据流：单次查询生命周期

```
用户输入
    │
    ▼
processUserInput()      ← 解析斜杠命令，构建 UserMessage
    │
    ▼
fetchSystemPromptParts() ← 工具描述 + CLAUDE.md 记忆 + 权限上下文
    │
    ▼
recordTranscript()       ← 持久化用户消息到磁盘 (JSONL)
    │
    ▼
┌─→ normalizeMessagesForAPI()  ← 去除 UI 专用字段，按需压缩
│   │
│   ▼
│   Claude API（流式）    ← POST /v1/messages with tools + system prompt
│   │
│   ├─ 文本块 ─────────→ yield 给消费者（SDK / REPL）
│   │
│   └─ tool_use 块?
│       │
│       ▼
│   StreamingToolExecutor ← 分区：并发安全 vs 串行
│       │
│       ▼
│   canUseTool()          ← 权限检查（hooks + 规则 + UI 提示）
│       │
│       ├─ DENY ─────────→ 追加 tool_result(error)，继续循环
│       │
│       └─ ALLOW
│           │
│           ▼
│       tool.call()        ← 执行工具（Bash、Read、Edit 等）
│           │
│           ▼
│       追加 tool_result   ← 写入 messages[]，recordTranscript()
│           │
└─────────┘                ← 循环回到 API 调用
    │
    ▼（stop_reason != "tool_use"）
yield 结果消息              ← 最终文本、用量、成本、session_id
```

## 4. 核心功能模块

### 4.1 代理循环（Agent Loop）

**最小代理循环**就是 AI agent 的本质：

```
用户 → messages[] → Claude API → 响应
                                  |
                        stop_reason == "tool_use"?
                       /                          \
                     是                            否
                      |                             |
                执行工具                         返回文本
                追加 tool_result
                循环回退 ──────────────→ messages[]
```

Claude Code 在这个最小循环之上构建了 12 层生产级机制（详见第 5.1 节）。

**核心文件**：`src/query.ts`（785KB，最大文件，包含完整代理循环逻辑）

### 4.2 工具系统（Tool System）

#### Tool 接口定义

每个工具是一个实现 `Tool<Input, Output, Progress>` 接口的对象：

```typescript
export type Tool<Input, Output, Progress> = {
  // 核心方法（必须实现）
  name: string
  inputSchema: ZodSchema           // 用 Zod 定义输入结构
  call(args, context, canUseTool, parentMessage, onProgress): Promise<ToolResult<Output>>
  checkPermissions(input, context): Promise<PermissionResult>
  description(input, options): Promise<string>
  prompt(...): Promise<string>     // 给 Claude 的工具说明
  
  // 能力声明
  isConcurrencySafe(input): boolean   // 是否可以并行执行？
  isReadOnly(input): boolean          // 是否无副作用？
  isDestructive?(input): boolean      // 是否不可逆？
  isEnabled(): boolean                // feature gate 检查
  
  // UI 渲染（React/Ink）
  renderToolUseMessage(input, options): React.ReactNode
  renderToolResultMessage(content, progress, options): React.ReactNode
  renderToolUseProgressMessage(progress, options): React.ReactNode
}
```

**工厂函数**：`buildTool(definition)` 为可选方法提供安全默认值。

#### 内置工具全景

```

#### BashTool 的精妙设计

BashTool 是最复杂的工具之一，包含 16 个文件：

- **安全分析**：`parseForSecurity()` 检测危险命令模式
- **命令语义分类**：区分搜索命令 / 读取命令 / 列表命令，决定 UI 折叠方式
- **进度阈值**：超过 2 秒显示进度动画，超过 15 秒允许用户中断
- **文件追踪**：记录 `rm, mv, cp, touch` 等命令的文件变更，用于 FileHistory 撤销

### 4.3 权限管控系统

权限系统是保证安全性的核心，工具调用前经过多级检查：

```
工具调用请求
      │
      ▼
validateInput()           ← 先验证输入合法性
      │
      ▼
PreToolUse Hooks          ← 用户自定义 shell 命令钩子（settings.json）
      │                     可以：批准、拒绝、修改输入
      ▼
Permission Rules          ← 规则引擎
  alwaysAllow: match → 自动允许
  alwaysDeny:  match → 自动拒绝
  alwaysAsk:   match → 始终询问
  规则来源: settings.json, CLI 参数, 本次会话决策
      │
      ▼ (无匹配规则)
自动分类器               ← (YOLO/自动模式) AI 分类器判断安全性
      │
      ▼ (分类器不确定)
交互式提示框              ← 用户看到工具名称 + 输入
  选项: 允许一次 / 始终允许 / 拒绝
      │
      ▼
checkPermissions()        ← 工具自身的安全逻辑（如路径沙箱）
      │
      ▼
APPROVED → tool.call()
```

**权限模式**：
- **默认模式**：危险操作每次都要确认
- **计划模式（Plan Mode）**：只允许读操作，禁止修改
- **自动模式（YOLO Mode）**：AI 自动判断，无需人工确认

### 4.4 上下文压缩（Context Compaction）

当对话历史超过模型上下文窗口时，自动触发压缩：

**三种压缩策略**：

| 策略 | 触发条件 | 机制 |
|------|---------|------|
| `autoCompact` | Token 数超过阈值 | 调用 Claude API 对旧消息做摘要 |
| `snipCompact` | `HISTORY_SNIP` feature flag | 删除冗余消息和过期标记 |
| `contextCollapse` | `CONTEXT_COLLAPSE` feature flag | 重构上下文结构 |

**压缩后的消息结构**：

```
messages[]
  ├── [早期对话的压缩摘要]
  ├── [compact_boundary 标记]
  ├── [最近消息 — 完整保留]
  │     user → assistant → tool_use → tool_result
  └── [当前轮次]
```

**关键常量**：
- `AUTOCOMPACT_BUFFER_TOKENS = 13,000`（触发压缩的缓冲）
- `MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES = 3`（失败熔断）
- `POST_COMPACT_MAX_FILES_TO_RESTORE = 5`（压缩后最多恢复 5 个文件到上下文）

### 4.5 多代理协作（Multi-Agent）

Claude Code 支持多种子代理模式：

#### 子代理类型

| 类型 | 创建方式 | 特点 |
|------|---------|------|
| `local_agent` | AgentTool（默认） | 独立进程内运行，全新的 messages[] |
| `fork` | AgentTool（fork 模式） | 子进程，共享文件缓存，新消息队列 |
| `worktree` | EnterWorktreeTool | 隔离的 git worktree + fork 子进程 |
| `remote_agent` | 桥接层 | 通过 bridge 连接到远程容器/会话 |
| `in_process_teammate` | TeamCreateTool | 同进程内，用户可见执行过程 |

#### 多代理通信协议

```
代理间通信工具：
├── SendMessageTool     → 代理到代理的消息传递（请求-响应模式）
├── TaskCreate/Update   → 共享任务看板
└── TeamCreate/Delete   → 团队生命周期管理
```

#### 协调器模式（Coordinator Mode）

特殊执行模式，一个协调器代理统一指挥多个工作代理：

- 协调器负责：规划、分配任务、合并结果
- 工作代理负责：研究、实现、验证
- 通过 `CLAUDE_CODE_COORDINATOR_MODE` 环境变量启用

#### Swarm 模式（功能门控）

```
主代理
  ├── 工作代理 A ──> 认领任务 1
  ├── 工作代理 B ──> 认领任务 2
  └── 工作代理 C ──> 认领任务 3
  
共享: 任务看板、消息收件箱
隔离: messages[]、文件缓存、工作目录
```

### 4.6 MCP 协议集成

MCP（Model Context Protocol）是 Anthropic 定义的工具扩展协议，允许外部服务为 Claude Code 提供额外工具：

**支持的传输协议**：

| 传输方式 | 说明 |
|---------|------|
| `stdio` | 生成子进程，通过 stdin/stdout 通信 |
| `sse` | HTTP Server-Sent Events（EventSource） |
| `http` | Streamable HTTP |
| `ws` | WebSocket |
| `sdk` | 进程内传输 |

**工具命名约定**：`mcp__<服务名>__<工具名>`

**认证方式**：
- OAuth 2.0（McpOAuthConfig）
- Cross-App Access（XAA / SEP-990）
- Header API Key

### 4.7 会话持久化

```
~/.claude/projects/<路径哈希>/sessions/
└── <session-id>.jsonl          ← 追加写入日志
    ├── {"type":"user",...}
    ├── {"type":"assistant",...}
    ├── {"type":"progress",...}  ← 工具执行进度
    └── {"type":"system","subtype":"compact_boundary",...}
```

**恢复模式**：
- `--continue`：恢复当前目录最后一个会话
- `--resume <id>`：恢复指定会话
- `--fork-session`：新会话 ID，复制历史记录

**写入策略**（性能优化）：

| 消息类型 | 写入策略 |
|---------|---------|
| 用户消息 | `await`（阻塞写入，确保崩溃恢复） |
| 助手消息 | fire-and-forget（保序队列） |
| 进度消息 | 内联写入（下次查询时去重） |

### 4.9 记忆系统（Memory / CLAUDE.md）

Claude Code 通过分层的 `CLAUDE.md` 文件为模型提供项目上下文：

**记忆文件查找顺序**：

```
~/.claude/CLAUDE.md                  ← 全局记忆
<project-root>/CLAUDE.md            ← 项目级记忆
<cwd>/CLAUDE.md                      ← 当前目录记忆
```

**记忆加载策略**：
- **惰性加载**：通过工具结果注入，而非放入系统提示词
- **Directory-aware**：从当前工作目录向上遍历加载
- **Skills**：`SkillTool` 可以加载特定领域的知识文档

**memdir（记忆目录）**：
- 存储在 `~/.claude/memdir/` 中的结构化记忆
- 支持 Dream Task 后台整固
- Feature flag `tengu_coral_fern` 控制

## 5. 技术亮点

### 5.1 十二层渐进式 Harness 机制

这是从源码中提炼出的最重要技术洞察：**构建生产级 AI agent 需要在基础循环之上叠加 12 层机制**。

```
s01  THE LOOP（基础循环）
     query.ts: while-true 循环 → Claude API → 检查 stop_reason → 执行工具 → 追加结果
     ──────────────────────────────────────────────────────────────────────
     "One loop & Bash is all you need"

s02  TOOL DISPATCH（工具分发）
     Tool.ts + tools.ts: 工具注册到分发表，循环不变，buildTool() 工厂函数提供安全默认值
     ──────────────────────────────────────────────────────────────────────
     "Adding a tool = adding one handler"

s03  PLANNING（规划）
     EnterPlanModeTool / ExitPlanModeTool + TodoWriteTool
     先列出步骤，再执行。据称将任务完成率翻倍。
     ──────────────────────────────────────────────────────────────────────
     "An agent without a plan drifts"

s04  SUB-AGENTS（子代理）
     AgentTool + forkSubagent.ts: 每个子代理获得全新 messages[]，保持主对话干净
     ──────────────────────────────────────────────────────────────────────
     "Break big tasks; clean context per subtask"

s05  KNOWLEDGE ON DEMAND（按需知识）
     SkillTool + memdir/: 通过 tool_result 注入，而非塞入系统提示词
     CLAUDE.md 文件按目录惰性加载
     ──────────────────────────────────────────────────────────────────────
     "Load knowledge when you need it"

s06  CONTEXT COMPRESSION（上下文压缩）
     services/compact/: autoCompact（摘要）+ snipCompact（裁剪）+ contextCollapse
     ──────────────────────────────────────────────────────────────────────
     "Context fills up; make room"

s07  PERSISTENT TASKS（持久化任务）
     TaskCreate/Update/Get/List: 基于文件的任务图，带状态跟踪和依赖管理
     ──────────────────────────────────────────────────────────────────────
     "Big goals → small tasks → disk"

s08  BACKGROUND TASKS（后台任务）

### 5.2 关键设计模式

| 模式 | 位置 | 用途 |
|------|------|------|
| **AsyncGenerator 流式传输** | `QueryEngine`, `query()` | 从 API 到消费者的全链路流式传输 |
| **Builder + Factory** | `buildTool()` | 工具定义的安全默认值 |
| **Branded Types（品牌类型）** | `SystemPrompt`, `asSystemPrompt()` | 防止 string/array 类型混淆 |
| **Feature Flags + DCE** | `feature()` from `bun:bundle` | 编译时死代码消除 |
| **Discriminated Unions（判别联合）** | `Message` 类型 | 类型安全的消息处理 |
| **Observer + State Machine** | `StreamingToolExecutor` | 工具执行生命周期追踪 |
| **Snapshot State（快照状态）** | `FileHistoryState` | 文件操作的撤销/重做 |
| **Ring Buffer（环形缓冲）** | 错误日志 | 长会话的有界内存 |
| **Fire-and-Forget Write** | `recordTranscript()` | 非阻塞持久化（保序队列） |
| **Lazy Schema** | `lazySchema()` | 延迟 Zod schema 求值，提升性能 |
| **Context Isolation** | `AsyncLocalStorage` | 共享进程中的每代理独立上下文 |
| **Circuit Breaker（熔断器）** | `MAX_CONSECUTIVE_AUTOCOMPACT_FAILURES` | 自动压缩失败保护 |

## 8. 代码质量观察

### 8.1 工程规范

- **Zod** 用于所有工具输入的运行时 schema 验证
- **TypeScript** `strict: false`（历史债务，推断类型为主）
- **Branded Types** 防止类型系统意外混淆（如 `SystemPrompt` vs `string`）
- **AsyncGenerator** 全链路流式传输，无中间 buffer
- **AsyncLocalStorage** 实现代理隔离上下文（类比 Node.js 中的线程本地存储）

### 8.2 性能设计

- **并行工具执行**：`StreamingToolExecutor` 自动将并发安全的工具并行化
- **LRU 文件缓存**：`readFileCache` 避免重复读取
- **惰性 Schema**：`lazySchema()` 延迟 Zod schema 求值
- **Fire-and-Forget 写入**：会话转录的异步持久化
- **Speculative execution（推测执行）**：提前预测并执行可能的工具调用

### 8.3 可靠性设计

- **熔断器**：连续压缩失败超过 3 次停止重试
- **指数退避**：API 重试、桥接重连均有退避机制
- **崩溃恢复**：用户消息阻塞写入，确保意外退出后可恢复
- **Ring Buffer 错误日志**：防止长会话内存溢出

### 8.4 编译时优化（Bun）

```
feature('FLAG_NAME')
  ├── true  → 代码保留在 bundle 中（Anthropic 内部构建）
  └── false → 代码被死代码消除（发布的 npm 包）
```

这使得 12MB 的发布 bundle 中只包含面向外部用户的代码，内部功能（108 个模块）被完全剥离。

## 9. 核心学习要点汇总

### 构建 AI Agent 的关键洞察

**1. 从最小循环开始**  
Agent = while-true + API 调用 + 工具执行。掌握这个最小闭环后，再叠加生产级机制。

**2. 工具系统的设计**  
用 Builder 模式定义工具，使工具注册与循环逻辑解耦。每个工具声明：能力（只读/破坏性/并发安全）、权限要求、UI 渲染方式。

**3. 权限系统不可简化**  
三级权限（配置规则 → 自动分类器 → 交互提示）是生产系统的必要设计，不能只有"允许/拒绝"两种状态。

**4. 上下文管理是长会话的关键**  
压缩策略（摘要 + 裁剪）使 Agent 能够处理超出上下文窗口的长任务，熔断器防止无限重试。

**5. 子代理隔离上下文**  
每个子代理拥有独立的 messages[] 是架构上的核心决策：保持主对话干净，防止上下文污染。

**6. 知识按需加载**  
将知识注入 tool_result 而非 system prompt，使得只有需要时才占用上下文窗口。

**7. 持久化策略要有差异**  
不同重要性的数据用不同写入策略：关键数据阻塞写入，次要数据 fire-and-forget。

**8. 终端 UI 可以用 React**  
Ink + React 将声明式 UI 带入终端，使复杂交互界面的开发效率大幅提升。
